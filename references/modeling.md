# 阶段 2-3:方案选择与模型搭建

核心原则:**大道至简 + 可解释性优先 + 诚实 + 忠于题目**。模型不是越复杂越好,而是越能讲清楚越好。

## 1. 大道至简:模型形态的选择偏好序

**从最简单、最可解释的模型开始,只有在简单模型确实无法解决问题时,才逐步增加复杂度。能停在前面就不要往后走。**

| 层级 | 模型类型 | 适用场景 | 优势 |
|---|---|---|---|
| **1** | **机理/结构模型**(幂律、对数线性、常/差分方程、排队论、优化模型) | 问题存在明确的物理/经济/社会规律 | 参数少、每个参数有明确业务含义、可解释性强 |
| **2** | **带统计推断的参数模型**(回归、弹性系数、假设检验、残差诊断) | 有数据支撑,需要量化不确定性 | 可给出置信区间、显著性检验、统计保证 |
| **3** | **机器学习模型**(随机森林、XGBoost、SVM) | 作为**非参数稳健性检验** | 与参数模型对照精度,验证参数设定无系统性偏差 |
| **4** | **集成/深度学习** | 题目明确要求"预测精度优先"且无可用机理时 | 必须伴随可解释性补救(特征重要性、SHAP、LIME) |

**典型应用示例**:
- 预测问题:先用对数线性回归或 ARIMA,再用随机森林做对照验证
- 优化问题:先建线性/整数规划模型,再考虑启发式算法
- 评价问题:先用 AHP 或 TOPSIS,再用熵权法做权重敏感性分析

**反面教训**:黑箱模型当主角 + 训练集 R² 冒充泛化 → 全无说服力。虚增复杂度(三个模型叠加但每层讲不清)→ 不如一个讲得清的模型。

## 2. 候选方案:每问 2~3 个,差异化

为每问给 2~3 个候选建模方案,遵循"大道至简"偏好序。每个方案写明:

```json
{
  "question": "Q1",
  "candidates": [
    {
      "name": "方案简称",
      "method": "方法名+简述",
      "core_math": "核心数学公式(LaTeX)",
      "algorithm": "算法步骤(自然语言,3-5步)",
      "verification": "验证计划(稳健性/敏感性/真实基线对照)"
    }
  ]
}
```

**要点**:
- 候选方案须**差异化**(不同模型族),不是同族微调。如 Q1 优化问题:候选1 线性规划,候选2 整数规划+贪心初始解,候选3 拉格朗日松弛。
- 每个方案都写验证计划,不写"验证"两个字糊弄。
- **每问必须指定一个"可用基线"(`baseline` 字段)**:能完成真实任务、产出可比指标,禁止玩具方法冒充(见 §2.1)。
- 默认选第一个候选(最简的)作为 `chosen`,除非用户在 CP2 点选其他。
- 自反思:每个方案的假设是否合理?参数是否有业务含义?是否可解释?反思日志落 `modeling_doc.json` 的 `reflection_log`。

### 2.1 基线对比门(硬门禁 G1)

**没有对比就没有说服力。** 每个 Qx 必须有一个真实、可比的基线,并在该问结尾给出"基线 vs 主方法 vs 备选"对比表。基线不是凑数,而是衡量主方法到底值不值得的标尺。

**基线怎么选(按题型):**

| 题型 | 合格基线 | 不合格(玩具)基线 |
|---|---|---|
| 分类 | 多数类预测、逻辑回归、简单决策树 | 随机猜测 |
| 回归/预测 | 均值/中位数、上一期值(naive)、一元线性回归 | 随手编的常数 |
| 优化 | 当前实际方案 / 历史排产 / 贪心解 | "随机可行解" |
| 评价 | 等权评分 | 拍脑袋系数 |

**对比表模板(每问一张,放该问末尾或"方案/模型对比汇总"章):**

| 方案 | 指标1 | 指标2 | 相对基线差异 | 结论/选择 |
|---|---|---|---|---|
| 基线 | ... | ... | — | 作为参照 |
| 主方法 | ... | ... | +x% / -y | 采纳,原因… |
| 备选 | ... | ... | ... | 未采纳,原因… |

- 差异必须给**数值**(+x% / -y 或绝对差),禁止"明显提升""最优"这类空话。
- 分类题补 ROC/PR 或混淆矩阵;回归题补残差图;优化题补方案差异条形图。
- 主方法最终指标必须来自**独立测试集**(见 `validation.md` §1.1),基线用同一划分、同一口径计算。
- 若主方法不如基线,**如实写并解释**——这比硬说"最优"更可信。

`modeling_doc.json` 每问增加 `baseline` 字段:`{"name": "...", "method": "...", "metrics": {...}, "why_comparable": "..."}`。

## 3. 小巧思:让模型"聪明但不复杂"

以下技巧不浮夸、可解释,能显著提升建模质量或求解效率。

### 3.1 枚举剪枝:从暴力到智能
**适用**:组合优化、排列组合、搜索匹配。

三种高效剪枝:

| 剪枝类型 | 适用场景 | 实现方法 | 效果 |
|---|---|---|---|
| 可行性剪枝 | 约束满足问题 | 检查当前部分解是否满足约束 | 减 50-90% 搜索空间 |
| 最优性剪枝 | 优化问题 | 比较当前解与已知最优 | 效果取决于问题结构 |
| 对称性剪枝 | 对称问题 | 识别并跳过对称等价状态 | 减 n! 级重复 |

**分支定界法**核心流程:
1. 定义搜索树(分支变量 + 节点状态)
2. 设计界(计算快、尽量紧,常用松弛)
3. 维护当前最优(找到更优可行解就更新 best)
4. 剪枝(`bound <= best` 最大化时丢弃子树)
5. 选择展开策略(DFS/BFS/最佳优先)
6. 尽早得到可行解(贪心求初始界,大幅提升剪枝效率)

**工程选型顺序**:小规模直接 DP/暴力 → NP-hard 中等规模要最优解用分支定界 → 大规模要近似解用启发式 → 能线性/整数规划建模交求解器(CPLEX/Gurobi/SCIP)。

### 3.2 目标可分离性 → O(1) 增量更新
**适用**:组合优化、调度、资源分配。

若目标可拆成各决策单元得分之和,单点移动增量:
$$\Delta F_{(i)}=\big[s_i(v',t')-s_i(v_i,t_i)\big]-\Phi\big[\psi(a')-\psi(a)\big]$$

预计算得分矩阵 + 各单元计数 → 贪心或局部搜索可处理大规模。通用变体:2-opt 两两交换、插入操作。

### 3.3 贪心机会成本
**适用**:分配、选址、匹配。

给候选打分时嵌入"失去的最优":
$$\rho_i(v)=\max\big\{0,\ \max_{\text{其他组合}} s_i-\max_{\text{在该位置}} s_i\big\}$$
不仅看自身得分,还看"不选这里最好的替代方案是什么"。

### 3.4 多随机重启
**适用**:任何依赖初始解的启发式(贪心、局部搜索、模拟退火、遗传)。

取 $N_{\text{restart}}=5\sim10$ 次随机重启中完整目标最高者。贪心+局部搜索易陷局部最优,多重启显著改善解质量,代价可控。

### 3.5 蒙特卡洛条件概率
**适用**:概率模型、风险评估、晋级概率、复杂系统模拟。

无法解析求解时,蒙特卡洛模拟 $N=10^4\sim10^5$ 次估计:事件概率、条件概率、期望方差。步骤:敏感性分析定随机变量 → 构造概率分布 → 抽样计算指标 → 整理期望/方差/分布/累积概率。

### 3.6 真实基线对照
**适用**:所有优化和改进类问题。

用真实世界数据(已结束的真实案例、公开权威来源)作基线,与模型结果逐指标对比。比虚构"朴素随机"基线有说服力得多。如:交通优化对比当前实际路况、生产调度对比历史排产、预测模型对比"上一期值"简单基准。

### 3.7 官方口径原样采用
**适用**:题目或实际场景给出明确公式、定义、约束时。

题目给的公式、动态更新规则、约束条件直接采用,不自行发明替代。自行定义与题目不同的口径(如自造旅行负担定义)→ 与题意冲突,评审一问就露馅。

### 3.8 其他通用小巧思

| 技巧 | 适用场景 | 说明 |
|---|---|---|
| 拉格朗日松弛 | 复杂约束优化 | 难处理约束放入目标,逐步调乘子 |
| 变量代换/无量纲化 | 微分方程、物理模型 | 减少参数数量,揭示本质规律 |
| 对偶问题 | 线性/凸优化 | 对偶更易求解,提供下界 |
| 分治策略 | 大规模问题 | 分解为子问题分别求解再整合 |
| 平滑处理 | 非光滑优化 | 光滑函数逼近,便于梯度算法 |

## 4. 可解释性:每步都要"验得明"

### 4.1 统计推断(参数模型必备)
- 弹性/系数估计值
- 标准误与 95% 置信区间
- t 值、F 检验、R²/调整 R²

### 4.2 残差诊断(三件套)
| 检验 | 目的 | 工具 |
|---|---|---|
| 正态性 | 误差是否正态 | QQ 图 + Shapiro-Wilk |
| 异方差 | 误差方差是否恒定 | 拟合值-残差图 + BP 检验 |
| 自相关 | 误差是否序列相关 | Durbin-Watson |

三个都通过,经典假设才立得住。

### 4.3 稳健性对照
用非参数模型(随机森林、梯度提升树)做同样任务:精度相当 → 参数设定无系统性偏差;差异大 → 检查参数模型假设是否被违反。

### 4.4 交叉验证
- 训练集做 K 折(K=5 或 10)
- **严禁**用训练集 R² 冒充测试精度
- 测试集无标签时,明确说明"用训练集 CV 作真实对比"

### 4.5 敏感性分析
- 权重/参数单维 ±20%~50%
- 归一化后看目标各维变动
- 回答"结论对参数敏感吗?"

## 5. 优化模型完整形式(学术规范硬要求)

凡涉及优化模型,在把目标、约束的公式列完后,**必须再给出完整形式**——"max + s.t. + 大括号括住全部约束":

```latex
\begin{equation}
\begin{aligned}
\max\quad & F(a)=\sum_{i\in\mathcal I} w_k\, f_k(a),\\
\mathrm{s.t.}\quad &
\left\{\begin{array}{ll}
\text{(候选域)}& a_i\in\mathcal F_i,\ \forall i,\\
\text{(容量)}& \sum_{i:d_i=d}\mathbf 1\{a_i\in C\}\le B_d^{\max},\ \forall d,\\
& \sum_i \mathbf 1\{a_i\in C\}\le B^{\max},\\
\text{(预算)}& \sum_{i:d_i=d}C_i(a_i)\le \mathrm{Bud}_d,\ \forall d.
\end{array}\right.
\end{aligned}
\label{eq:p2model}
\end{equation}
```

约束行写法:`\text{(约束名)}& 公式,\ \forall 下标`。同构逐日约束可并排多行,但每行必须宽度安全(超宽会 overfull)。

## 6. 诚实:坏结果也是好素材(但有前提)

> **重要前提**:以下"如实披露"原则,建立在**已尝试多种方法、结果尚可接受**的基础上。结果差时先改进,不要直接提交差结果。

- **改善小就写小**:尝试多种方法后改善有限,如实写"改善温和,原因:...",给具体数值(如"8/24 场为正,均值 0.77%")。
- **退化项如实披露**:公平性从 1.000 降到 0.500?写"诚实退化",反而增加可信度——前提是已尝试多种权重组合、约束松弛后的最优折中。
- **数据与假设冲突时说明**:真实数据与模型假设不符,如实披露并分析原因,而非掩盖。
- **模型评价一节因此有话可说**:优点(机理清楚、可解释、计算高效)/缺点(样本量限制、假设简化、参数敏感性)/改进方向(更细粒度数据、更复杂模型、更大样本)。

**结果很差时的改进路径**:

| 问题类型 | 改进策略 |
|---|---|
| 预测精度差 | 检查特征工程 → 非线性变换 → 引入交互项 → 换模型族 |
| 优化解质量差 | 检查约束是否过紧 → 不同初始解 → 增加重启次数 → 换启发式 |
| 收敛困难 | 检查目标光滑性 → 松弛约束 → 调步长/学习率 |
| 过拟合严重 | 增加正则化 → 减少特征 → 增加数据 → 简化模型 |

**底线**:论文中呈现的结果必须是经过多轮尝试后"当前能做到的最好"。仍不满意,在模型评价中诚实说明局限性和未来改进方向。

## 7. 反面教材(常见踩坑)

| 坑 | 后果 | 如何避免 |
|---|---|---|
| 黑箱模型当主角 + 训练集 R² 冒充泛化 | 全无说服力 | 简单模型为主,黑箱仅作对照 |
| 单位与口径不一致 | 结果自相矛盾 | 全文+代码+README 统一 |
| 自行发明与题目不同的口径 | 与题意冲突 | 严格采用官方定义 |
| 虚增复杂度:三个模型叠加但每层讲不清 | 不如一个讲得清的模型 | 大道至简,逐层论证 |
| 忽视模型假设的验证 | 结论不可靠 | 残差诊断、敏感性分析必做 |
| 枚举不加剪枝 | 指数级爆炸,无法求解 | 始终考虑可行性/最优性/对称性剪枝 |
