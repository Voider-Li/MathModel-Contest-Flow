# 阶段 5:论文写作规范

论文是唯一交付物。读者(评委)只看论文,代码只是支撑。论文要读起来像**资深参赛者手写**,不是 AI 腔。本节规范覆盖结构、长度、公式、排版、降 AI 味、图表呼应、空白调控。

## 1. cumcmthesis 结构骨架(国赛模板,通用)

基于 cumcmthesis 模板(全国大学生数学建模竞赛官方模板),其他赛事可类推:

```latex
\documentclass[withoutpreface,bwprint]{cumcmthesis}  % 电子版提交,去掉封面与编号页
% 必须用 xelatex 编译(不是 pdflatex)
\usepackage{tikz}\usetikzlibrary{arrows.meta, positioning, shapes.geometric}
\usepackage{booktabs}    % 三线表
\usepackage{url}
\usepackage{subcaption}  % 子图
\usepackage{listings}    % 代码
\usepackage{amsmath, amssymb}
```

> **类文件从哪来(cumcmthesis.cls):** 本 skill 在 `templates/cumcmthesis/cumcmthesis.cls` **自带一份离线副本**(官方 cumcmthesis v2.9,2026/08/26,随 CTeX 发布)。xelatex 编译时要求 `cumcmthesis.cls` 在论文工作目录(或 TEXINPUTS)内可搜到,而 skill 里的副本不会被自动加载,所以**阶段 5 编译前必须把它复制到 `05_paper/` 与 `main.tex` 同目录**(若本机已 `kpsewhich cumcmthesis.cls` 能找到,则可不复制,以系统版为准)。不要只靠"口头引用"类名——否则报 `File 'cumcmthesis.cls' not found`。

**论文正文结构(按此顺序)**:

| 部分 | 长度 | 要点 |
|---|---|---|
| 标题 + 摘要 + 关键词 | **1 页内,摘要与标题同页** | 摘要铺满约 80% 版心;按小问成段(背景→针对问题一/二…);数值与重点方法加粗 |
| 1 问题重述 | 1-1.5 页 | 简洁转述,不抄题;含背景、要解决的问题 |
| 2 问题分析 | 1-2 页 | 每问一整段:难点、思路、选型理由;**节末放全文唯一一张总体架构图** |
| 3 **数据预处理与独立数据挖掘** | 2-3 页 | **独立成章(门禁 G2)**,七项内容见 `data-mining.md` §2;结尾写"发现→影响" |
| 4 模型假设与符号说明 | 1.5-2 页 | 假设 4~6 条 + 三线表符号说明;先出现的先列 |
| 5 各子问题建模与求解 | 主体,每问 5-8 页 | 每问:开头 TikZ 流程图 → 机理/公式 → 求解算法 → 结果与分析 |
| 6 **方案与模型对比汇总** | 0.5-1 页 | **门禁 G1**:基线 vs 主方法 vs 备选对比总表,差异给数值 |
| 7 **模型检验与评价** | 1.5-2 页 | **独立成章(门禁 G3/G4)**:划分协议、测试集指标、CV 对照、敏感性、失败样本、泛化局限,见 `validation.md` §2 |
| 8 结论、优缺点与推广 | 1 页 | 收束全文;优缺点与改进方向三节 |
| 参考文献 | 1-2 页 | GB/T 7714,**全部真实可查**(门禁 G5,见 `literature.md`),含数据来源 |
| 附录 | 不计入正文页数 | 附录 A 文件清单、附录 B 完整代码(`\lstinputlisting`) |

> **数据挖掘章(第 3 章)与模型检验章(第 7 章)是硬门禁要求,必须独立成章**,不能散落进各问。写法分别见 `data-mining.md` 与 `validation.md`;两章内容都只引用**冻结结果**,不自造数字(门禁 G6)。

**正文总页数硬约束**:正文(标题摘要 → 结论与推广 + 参考文献,**不含附录**)**硬性不超过 30 页**,且应落在 **21–30 页**区间。低于 21 页说明内容偏薄(通常是分析不透、结果解读太少),高于 30 页直接违规,必须压缩。写作过程中每编译一次就用 `scripts/check_layout.py` 看一次页数,别等到最后才发现超了 8 页——那时候压缩会伤筋动骨。页数调控手段见第 7.5 节。

**节奏铁律**:文字、公式、图表交替铺开。任何一整页纯文字或纯公式都是排版事故——用图表和数字切碎。反过来,任何一整页几乎全是图也是排版事故:**单页图表视觉占位不得超过版心的 2/3**,且**严禁两图直接相邻而中间无正文**(详见第 6 节)。一页最多两张图表为宜。

## 2. 各部分写作要求(逐章)

### 2.1 标题、摘要、关键词

**标题**:
- 简明、清晰、准确,直接体现研究对象、核心问题及所用模型/方法,避免模糊表述。
- 格式参考"基于 XX 算法的 XX 优化研究",要突出独特之处和创新点。
- 字数 ≤ 20 字。生成 3 个差异化备选。

**摘要**(第一优先级):
- 篇幅 ≤ 1 页,纯文字,禁止表格、图表、公式。
- **标题和摘要必须同一页**。若摘要超长把正文挤到第 2 页,压缩摘要文字(删修饰句、留关键数字),而不是放宽页边距。
- **填充要求(硬性)**:摘要正文应铺满约 **80% 版心**(通常 600–900 字,以实际铺满、与标题同页为准),不要稀稀拉拉几行凑数;若不足则补关键分析,若超 1 页则压缩修饰句、只留关键数字,绝不放宽页边距。
- 结构(按"**成段**"组织,禁止用 itemize/enumerate 分点列表,全用自然段):
  - 第 1 段·**问题背景**:2-3 句,说明研究背景、意义、核心问题。
  - 第 2 段起·**逐问成段**,统一以"**针对问题一**,……"开头(问题二、三……同样句式,依次类推),每段覆盖:简化的问题核心 + 模型数学归类 + 建模思想 + 算法求解思路 + 建模特点(含优点、检验方式、灵敏度分析)+ 量化主要结果/结论。
  - 末段·**推广与应用**:模型推广场景 + 灵敏度分析 + 优缺点 + 改进方向。
- **加粗规则(硬性)**:所有关键**数值**(结果数字、阈值、指标)与重点**方法/模型名**一律加粗,便于评委一眼抓重点(如 **R²=0.592**、**基于熵权-TOPSIS 综合评价**、**基分 34.91**、**遗传算法求解**)。
- 必须包含"问题""模型""算法"等关键字眼,完整覆盖"问题、模型、算法、结论、特色"五大核心。
- 摘要里不要出现未定义的符号或引用编号。

**关键词**:3-5 个,至少包含三类——①核心问题;②所用模型;③算法/创新点。

### 2.2 问题重述
- 简洁转述,不抄题;含背景、要解决的问题。
- 1-1.5 页足够,不要长篇抄题面。

### 2.3 模型假设
- 4~6 条,分条列出,每条一句话,独立明确。
- 假设要能被正文用到,不写用不上的假设。
- 分类:
  1. 基于题目条件的假设(题目明确信息转化)
  2. 简化性假设(忽略小概率事件、剔除次要因素)
  3. 模型适配性假设(如博弈论"参与者理性"、回归"扰动项正态")
  4. 参数/分布假设
  5. 场景边界假设
- 每条用严格、确切语言,避免"合理假设""显然成立"等无依据表述。
- 按"基础层次→建模层次→数据层次"排序,基础假设在前。

### 2.4 符号说明
- 三线表(`booktabs`):符号 & 含义 & 单位。
- 先出现的先列,与正文符号一一对应。
- 1-2 页。

### 2.5 问题分析
- 每问一整段(不分点),按"问题拆解→问题特点→建模困难→解决思路→建模方向"展开。
- 三维回答框架:针对整体问题及每个小问,明确"需要做什么(核心任务)→ 需要达到什么目标(量化/定性原则)→ 需要怎么做(初步思路)"。
- 数据驱动:若题目提供附件数据,单独设"数据预处理分析"小节(数据来源、缺失值/异常值处理、关键统计量、数据分布特征)。
- 分析结尾明确指向具体模型类型,实现分析与建模的无缝衔接。
- **本节末尾放全文唯一一张「总体架构图」**:用 `skills/tikz-architecture-diagram` 子 skill 绘制的分层架构图(数据层 → 模型层 → 求解层 → 结果层 → 结论层),让评委在读正文前先看懂全局骨架。配 100–150 字 caption,`[H]` 固定在本节内,不许漂到下一节。**注意与各问流程图分工**:总体架构图全文只此一张、放这里;各小问的求解流程图仍按 `visualization.md` 第 5.1.1 节的蛇形(横向)TikZ 模板绘制、放在各问"模型建立与求解"开头,两者不可互相替代。
- 1-2 页(含架构图)。

### 2.6 模型建立与求解(主体,每问 5-8 页)
**每问结构**:
1. 开头一张 TikZ 流程图(`\resizebox{0.92\textwidth}{!}`)。
2. 建模思想(机理假设 + 结构模型推导)。
3. 公式(完整优化模型给 max + s.t. + 大括号形式,见第 3 节)。
4. 算法步骤(自然语言 3-5 步,或算法伪代码)。
5. 求解结果(表格 + 图,数值标注齐全)。
6. 结果与分析(解读关键数字,与基线对比,敏感性分析)。

**模型建立写作要点**:
- 基本模型(数学公式、方案等)要求完整、正确、简明。
- 简化模型要明确说明(简化思想、依据),简化后模型尽可能完整给出。
- 模型要实用、有效,以解决问题有效为原则。**不追求数学上高深难**,能用初等方法就不用高级方法,能用简单方法就不用复杂方法,能用更多人看懂的方法就不用少数人看懂的方法。
- 鼓励创新,但要切实,不离题标新立异。创新可出现在:模型本身与简化策略、模型求解、结果表示/分析/检验、推广部分。
- 分析中肯确切、术语专业内行、原理依据正确明确、表述简明、关键步骤列出。忌外行话、术语不明确、表述混乱冗长。
- **每问公式推导 / 定义 / 约束 / 证明不少于 10 处(主要且必要)**:每个子问题在建模与求解中应给出 ≥10 个有实质的式子或论断——包括公式推导、关键定义、约束条件(s.t. 项)、数学命题及其证明/论证,分散在各小节支撑该问。三条红线:**①只写主要且必要的,不要为凑数强加**无关或牵强的式子;**②不要与前文重复**(定义/约束若已在前面小问或假设中给出,后续只引用不重抄);**③若某问确实内容较浅、实在写不出 10 个有实质的,不强求**——以"写出来的都有用、不水字数"为准,宁缺毋滥。

**模型求解写作要点**:
- 建立数学命题时:命题叙述符合数学命题规范,尽可能论证严密。
- 说明计算方法或算法的原理、思想、依据、步骤;采用现有软件时说明采用理由与软件名称。
- 计算过程中间结果可要可不要的不要列出。
- 设法算出合理的数值结果。

**分章节生成(防截断)**:
- 每问先规划 3~5 个小节(`\subsection`),使该章内容完整、篇幅充足(每小节数百到千字)。
- 再逐小节生成 LaTeX 内容,每节输出短不截断。
- 每节以 `\subsection{标题}` 开头,含必要的数学公式(equation 环境并 `\label`)、算法步骤与量化结果。

### 2.7 数据预处理与独立数据挖掘章(硬门禁 G2)
- **独立成章**,不散落进各问;内容七项见 `data-mining.md` §2。
- 结构建议:数据来源与字段字典 → 缺失/离群/非法值处理(给依据)→ 单变量与目标分布 → 相关共线与分组差异 → 时序轨迹(如有)→ 特征工程与防泄漏标注 → **数据挖掘结论对建模选择的直接影响**。
- 图要配 100–150 字解读;统计量只引 `results/` 里的真实值(冻结后)。
- 结尾用 3~5 条"**[发现] → [影响]**"收束,明确指向第 5 章各问的选型。

### 2.8 方案与模型对比汇总章(硬门禁 G1)
- 汇总各问的"基线 vs 主方法 vs 备选"对比表(模板见 `modeling.md` §2.1),一张总表 + 关键图。
- 差异给数值;主方法指标注明来自独立测试集。
- 若某问主方法不如基线,如实写并解释,不粉饰。

### 2.9 模型检验与评价章(硬门禁 G3/G4)
- **独立成章**,七项清单见 `validation.md` §2:划分协议 → 训练/验证/测试规模 → **测试集最终指标** → CV 与测试集对照 → 阈值/参数敏感性 → 失败样本分析 → 泛化性与局限。
- 必须显式出现"测试集"字样并标注;禁止用训练集 R²/CV 冒充测试精度。
- 失败样本要给具体案例(漏报/误报/异常),不写"个别样本"。
- 数据泄露自查六条(见 `validation.md` §4)在写作时再核一遍。

### 2.10 结论、优缺点与推广
- 优点 / 缺点 / 改进方向,三节,1 页足够。
- 优点:机理清楚、可解释、计算高效。
- 缺点:样本量限制、假设简化、参数敏感性。
- 改进方向:更细粒度数据、更复杂模型、更大样本。
- 推广:模型能外推到哪些相邻场景、需要什么条件。

### 2.11 参考文献(硬门禁 G5)
- 按 GB/T 7714 著录,**逐条真实可查**(刊名、年份、卷期、页码、DOI/URL、检索日期),不编造。
- 一律 `\cite{key}` 自动编号,**禁止硬编码"文献[5]"**;每条都被正文实际引用。
- 数据来源(真实赛程等)作为独立文献列出,注明来源网站与检索日期。
- 建库与核验流程见 `literature.md`。

### 2.12 附录
- 附录 A:文件清单(支撑材料)。
- 附录 B:完整代码(`\lstinputlisting` 自动加载,与交付 zip 同一份)。

## 3. 公式规范

### 3.1 数量与分布
- 公式集中在"机理建模、推导、算法定义"处,**不堆砌**;能用文字说清的不要公式化。
- 每个公式**必须被正文引用**(`\eqref`)或用文字点名,不出现"孤儿公式"。
- 关键公式给编号,次要推导放文中 inline 或省略。
- **公式数量合适**:不是越多越好。能讲清机理的最少公式即可。

### 3.2 完整优化模型形式(学术规范硬要求)
凡涉及优化模型,列完目标、约束后,**必须再给出完整形式**——"max + s.t. + 大括号括住全部约束"(见 `modeling.md` 第 5 节代码)。

约束行写法:`\text{(约束名)}& 公式,\ \forall 下标`。同构逐日约束可并排多行,但每行必须宽度安全。

### 3.3 公式/图/表代码之后必须留空行(反复踩坑的顶格问题)
LaTeX 中,公式(`equation`/`align`)、图(`figure`)、表(`table`)的环境代码之后,若紧接的正文**没有空行**,会被当作该环境的延续行,**新段落首行不缩进(顶格)**;只有中间留一个空行,才会被识别为"新段落",首行缩进两格。这是中文论文排版最常踩、编译器又不报错的坑。

**铁律:**
- 公式 / 图 / 表环境结束后,若下一句是正常正文(新段落起段),**必须留一个空行**:

```latex
\end{equation}

  该段落首行缩进两格,不顶格。

\begin{figure}[H]
  ...
\end{figure}

  图后正文同样要留空行再起段。
```

- **唯一例外:紧接"式中:"**。公式之后若紧跟"式中:$a$ 表示……"解释符号,这是同一段落的自然延续,**不要留空行**,直接连着写——否则"式中:"会被误判成新段落、凭空多出两格缩进:

```latex
\end{equation}
式中:$a$ 表示……;$b$ 表示……。
```

- **所有公式(equation/align)、图(figure)、表(table)后接正文处都检查一遍空行。** 此项靠人工目检源码(`check_layout.py` 不覆盖,因为编译能过但渲染会顶格)。

### 3.4 大公式排版
- 长约束行**拆分**(一个约束占一行),不要挤在一行造成 40pt+ 的 overfull。
- 大括号 array 内行距用 `\\[1pt]`~`\\[3pt]` 紧排,7 行约束也能控制在 ~110pt 高。
- 符号首次出现要定义(正文或符号表)。

## 4. 尽量不分点叙述

- **正文用连贯段落**,少用 bullet / 分点。需要并列时用三线表或"首先/其次/再次/最后"衔接。
- 分点只保留在真正合适的地方:模型假设、算法步骤、模型评价的优缺点(那里分点最自然)。
- 理由:分点叙述读起来像提纲,不像论文;段落化的论证才显"建模功夫"。

## 5. 降 AI 味(核心要求,贯穿所有章节)

论文读起来要像资深参赛者手写,不是 AI 腔。审查并改写以下 AI 生成痕迹:

1. **破折号"——"过度使用**:删除或改写。一处用破折号是强调,处处用就是 AI 腔。
2. **三段式"xx-xx-xx"、"xx+xx+xx"的堆砌表述**:删除。如"高效-精准-可解释"这种三连,读着像营销文案。
3. **数字与中文、单位之间不恰当的空白空格**:删去。如"提升 20 %"应为"提升20%","R² = 0.592"在正文里看场合。
4. **貌似高级、故弄玄虚实则不讲人话的词语**:尽可能一目了然、讲人话。如"该范式实现了...的赋能"→"这个方法能..."。
5. **套话**:"值得注意的是""综上所述""不言而喻""众所周知""总而言之"——删或改。
6. **否定式排比**:"不仅...还...""既...又...""无论是...还是..."堆叠——克制用。
7. **过多连接性短语**:"首先""其次""再次""最后""此外""另外""与此同时"——连续段落全靠这些串,读着像提纲。
8. **以 -ing 结尾的肤浅分析**(中文里类似"xx性地""xx化地"):删。
9. **夸大的象征意义**:"这标志着...的新纪元""为...奠定了坚实基础"——删。
10. **宣传性语言**:"卓越的""完美的""革命性的"——删。

**保持学术严谨与专业性,但语言自然流畅,像资深参赛者手写。**

### 5.1 各部分长度合适(不冗长)
- 每部分长度见第 1 节表格。超长部分压缩,删修饰句、留关键数字与论证。
- 每问 5-8 页,不要为了凑页数灌水。一段说清的事不要分两段。
- **图表不重复描述**:图内已有数值标注时,正文只点最关键的,不重复每个数。
- **不堆砌**:不堆公式、不堆图表、不堆术语。能用一个公式说清的不用三个。

## 6. 图表排版硬规范(就近、说明、占比)

图表排版是版面事故的重灾区。LaTeX 的浮动体机制会让图表**自己漂走**,不加约束时一张图可能飘到三页之后,读者翻回去找图、评委看不懂对应关系,这是纯粹的白送扣分。本节四条规则都是硬性的,交付前用 `scripts/check_layout.py` 逐条机检。

### 6.1 图表必须与说明文字就近(硬性)

**要求**:图/表必须与正文中首次引用它的位置**同页或相邻页**,且**内容上紧随**——先有引用它的那句话,再出现图表,不允许图表跑到引用之前。

**为什么必须显式约束**:`\begin{figure}` 默认的 `[htbp]` 允许 LaTeX 把浮动体推到"页顶、页底、单独浮动页"甚至章末。当一页排不下时它会顺延到后面若干页,于是"如图 5 所示"在第 12 页、图 5 实际印在第 15 页。各部件飘移是 LaTeX 的既定行为,不是偶发 bug,必须靠下面的手段锁死。

**做法(按可靠性从高到低)**:

1. **一律用 `[H]` 强制就地固定**。需要 preamble 里 `\usepackage{float}`:
   ```latex
   \begin{figure}[H]     % H = HERE,就在这,不许漂
     \centering
     \includegraphics[width=0.85\textwidth]{figures/Q1_各赛季观众数时序折线图.png}
     \caption{……100-150 字长说明……}
     \label{fig:q1-attend}
   \end{figure}
   ```
   `[H]` 是本 skill 的**默认选择**。代价是若当前页剩余空间不足,`[H]` 会把图整体推到下一页顶部并在本页留白——此时按第 7 节 playbook 调段落,而不是退回 `[htbp]`。
2. **源码位置紧随引用段落**:把 `figure` 环境写在"如图~\ref{...}所示……"那一段的**段末之后**,不要提前几段写、也不要攒到小节末尾集中放。源码顺序 ≈ 输出顺序,这是最省事的就近手段。
3. **`\FloatBarrier` 拦截跨节漂移**:preamble 加 `\usepackage{placeins}`,在每个 `\subsection` 前(或章节切换处)插 `\FloatBarrier`,确保上一节的图表不会漂进下一节。给 `placeins` 传 `[section]` 选项可自动在每节前设栅栏。
4. **大图单独成页时主动排版**:若图确实高到本页放不下(如满幅架构图),用 `\clearpage` 主动把它连同引用段一起送到新页开头,而不是任其漂移。

**自检**:`python scripts/check_layout.py main.pdf` 的 `[3] 图表就近` 段会报出"说明在第 X 页、首次引用在第 Y 页、相隔 N 页"以及"孤儿图表(正文无引用)"。任何一条非 OK 都要修。

### 6.2 图表说明文字写 100–150 字(硬性)

**要求**:每个 `\caption{}` 的说明文字**100–150 字**。这不是光秃的标题,是一段能独立读懂的说明。

**为什么**:评委翻论文时经常先看图表再看正文。一句"图 3 求解结果"什么信息都没给,读者必须回正文找上下文;而 100–150 字的说明能让图表**脱离正文自解释**——这是期刊插图的通行写法,也是拉开档次的细节。上限 150 字则是防止 caption 长到反过来挤占版面、抢正文的戏。

**写法配方**(按此四段拼,自然凑到 100–150 字):

1. **这是什么**(20–30 字):图表对象、数据范围、横纵轴或表列的含义。
2. **怎么来的**(20–40 字):用了什么模型/算法/参数得到,数据来自哪个附件或哪一步求解。
3. **关键数字**(30–50 字):图里最该被注意的数值——峰值、拐点、阈值、最优解、对比改善幅度,带单位。
4. **说明什么**(20–30 字):由此得到的结论或它支撑正文哪个论断。

示例(约 135 字):

```latex
\caption{各赛季观众数时序变化与幂律拟合结果。横轴为赛季序号,纵轴为单场
平均观众数(万人),散点为附件 1 实测值,实线为幂律模型 $y=ax^{b}$ 的拟合
曲线。参数估计得 $a=12.4$、$b=0.38$,决定系数 $R^{2}=0.592$。观众数在
第 6 赛季出现明显拐点,由年均增长 8.2\% 降至 2.1\%,增速放缓的转折与
场馆扩容完成的时点吻合,说明容量约束是前期增长的主要驱动因素。}
```

**注意**:

- 字数按中文字数统计口径(汉字数 + 数字/字母串各计 1 字),`scripts/check_layout.py` 用同一口径,直接解析 `.tex` 源码里的 `\caption{}`,并报出源码行号。
- caption 里可以有 `\%`、行内公式、`\ref`,但**不要塞 `\cite`**,也不要出现未定义符号。
- 表题同样 100–150 字。表题按惯例放表格**上方**(`\caption` 写在 `\begin{tabular}` 之前),图题放图**下方**,全文统一。
- 长 caption 不影响"图题风格统一":统一体现在**开头句式**上(如都以"问题二:"或都以对象名起头),不是靠长度一致。

### 6.3 单页图表占比不超过 2/3,且严禁图挨图(硬性)

**要求**:

1. 单页内图表(含图形本体,不含 caption)的**视觉占位不超过版心高度的 2/3**。
2. **不允许两张图直接相邻而中间没有正文**。caption 不算正文——两图之间只有 caption 也算违规。

**为什么**:占比一超,那页翻开就是"全是图"的观感,评委会认为作者在用图凑页数、缺乏分析。图挨图更糟:两张图连排,中间连一句解读都没有,等于把解释工作全甩给读者。数模论文的分值在**分析**上,图只是证据。

**做法**:

- **控制单图高度**:`\includegraphics[width=0.85\textwidth]` 起步(宽 > 高的图约占版心 0.4 倍高度),满幅图最多 `0.95\textwidth`。禁止用 `height=\textheight` 之类把图拉满页。TikZ 流程图用 `\resizebox{0.92\textwidth}{!}` 控宽,高度自动按比例。
- **两图之间必须垫正文**:至少 40 字(约 2 行)对上一张图的解读,再引出下一张图。写不出 40 字的解读,说明这张图本身没必要放——删掉或与前图合并为子图。
- **拆页**:一页已有两张图还想放第三张,把第三张连同其解读段一起推到下一页(`\clearpage` 或调整段落),不要硬塞。
- **合并**:同一指标的多张小图改用 `subcaption` 拼成一张多子图(一行最多 3 个,字号调大),整体仍受 2/3 约束。

**自检**:`scripts/check_layout.py` 的 `[1]` 段直接给出每页"图表视觉占位 X%"与"图挨图——两图形带之间仅 N 字正文"。脚本把位图与 TikZ 矢量绘制都算进图形带,所以流程图、架构图、三线表的表格线同样计入。

### 6.4 图表与正文的呼应

- 每张图/表都要被正文 `\ref` 引用,并在正文里**解读出关键数字**(图里的最高值、阈值、对比结论),不能让图自说自话。
- 图题、表题风格统一("问题二: …"、"表4: …"),编号连续。
- **图内已有直接数值标注时,正文不必重复每个数**,只点最关键的。避免图表重复描述。caption 里已给的关键数字,正文只需点最核心的一两个,不要整段抄一遍 caption。
- 一页最多两张图表为宜,不堆砌。

### 6.5 preamble 需要的宏包

为支撑 6.1–6.3,preamble 必须包含:

```latex
\usepackage{float}       % [H] 强制就地固定
\usepackage{placeins}    % \FloatBarrier 拦截跨节漂移
\usepackage{graphicx}
\usepackage{subcaption}  % 多子图
\usepackage{caption}     % 可选:统一 caption 字号与对齐
```

> **编译前置:`cumcmthesis.cls` 必须就位。** 上面这些宏包里,`float`、`graphicx`、`ctex`、`amsmath` 等已由 `cumcmthesis.cls` 内部 `\RequirePackage` 加载,无需重复;但 `placeins`、`caption`、`subcaption`、`tikz` 仍需在 preamble 显式写。`cumcmthesis.cls` 本身(本 skill 副本在 `templates/cumcmthesis/`)要在 `main.tex` 同目录——见第 1 节"类文件从哪来"。

`caption` 宏包可用来把长说明设成小一号字并两端对齐,读起来更像期刊插图:

```latex
\captionsetup{font=small, labelfont=bf, justification=justified,
              singlelinecheck=false, skip=4pt}
```

## 7. 不要有大片空白(playbook)

### 7.1 先测量,别靠猜
编译后用 pdfplumber 逐页量正文底部空白(排除页脚页码):

```python
import pdfplumber
pdf = pdfplumber.open('main.pdf')
for pg in range(len(pdf.pages)):
    p = pdf.pages[pg]
    words = [w for w in p.extract_words() if w['bottom'] < 770]  # 排除页脚
    if not words: continue
    blank = 770 - max(w['bottom'] for w in words)
    if blank > 90: print(f'page {pg+1}: {blank:.0f}pt 空白')
```

目标:每页底部空白 < ~90pt。超出进修复菜单。

### 7.2 修复手段(按侵入性从小到大)
1. **加引导/衔接段**(首选):在问题段落前补 1-2 句自然衔接。自然填充,不灌水。
2. **压缩大公式**:拆长行、合并同构约束、`\\[1pt]` 紧排。
3. **调整段落边界**:在合适处断句/合并段落,让断页点落在想要的位置。
4. **移动图表位置**:`[H]`(float 包)固定就近,或 `tbp` 放行让 LaTeX 自己排;把大表/大图移去下一页开头。
5. **`\nopagebreak` / `\samepage`**:防表格后紧跟段落被拆到两页。
6. **局部留白**:某页末尾有图引出的自然留白 < 90pt 可接受,不必强求填满。

### 7.3 大方程导致段落分页割裂
现象:段前几行留页底、其余跨页,页底留大空白。根因:大方程不可拆分、段落被 widow/orphan 规则挤开。解法:缩方程高度(拆行 + `\\[1pt]`)+ 收敛段前句(删冗余符号定义、合并句子)。

### 7.4 overfull 处理
`grep -n "Overfull" main.log` 定位。> 10pt 的必须修:长公式拆行、缩短约束文本、`\resizebox` 包裹超宽 TikZ 图。摘要里 < 2pt 的小溢出可容忍。

### 7.5 正文页数调控(硬性 ≤ 30 页,目标 21–30 页)

先量:`python scripts/check_layout.py main.pdf` 或 `pdfinfo main.pdf | grep Pages` 再减去附录页数。脚本会自动探测"附录"标题所在页来切分正文与附录,探测不准时用 `--body-end N` 手动指定。

**超过 30 页(必须压,按侵入性从小到大)**:

1. **砍附录外的代码/长表**:正文里的大段代码、逐行结果表移进附录,正文只留汇总表。这一步通常能省 2–4 页。
2. **压缩重复解读**:同一结论在图 caption、正文、小节小结里说了三遍——只留正文一处(caption 100–150 字已承担了图表自解释的职责)。
3. **删冗余图表**:表达同一指标的图与表二选一(见 `review.md` 浮夸性检查);一问的图从 6 张压到 4 张,留最能说明问题的。
4. **合并小节**:把 `\subsubsection` 层级拉平成段落,减少标题占行与段前段后间距。
5. **压缩公式排版**:长约束拆行改并排、`\\[1pt]` 紧排、次要推导改行内公式。
6. **删问题重述里的抄题内容**:重述压到 1 页内,题面细节靠符号表承载。
7. **最后才动版式**:行距、页边距属于赛规范围,多数赛事禁止私改模板参数——**不要靠改 `\geometry` 来凑页数**,这是违规风险。

**不足 21 页(要补,但绝不灌水)**:

1. **补结果解读**:每张图后补 40–80 字,讲清"这个数说明什么、与基线差多少、为什么合理"。这是最该补的地方,也是评分点。
2. **补敏感性/稳健性分析**:关键参数扰动 ±10% 看结论是否翻转,配一张对比图。既充实页数又是加分项。
3. **补模型假设的合理性论证**:每条假设为什么成立、若不成立影响多大。
4. **补算法步骤与复杂度说明**:把"调用求解器"展开成初始化、迭代、停止条件、复杂度。
5. **补数据预处理小节**:缺失值与异常值怎么处理、关键统计量、分布特征,配 1–2 张分布图。
6. **禁止的凑页手段**:拉大行距、图片放大到失真、复制粘贴式排比段、把同一张图换配色再放一次——审稿一眼能看出来。

## 9. 论文手定图单

论文手在写论文前先定图单,三类图各有归属:

- **总体架构图**(`type=arch`):全文**仅 1 张**,放问题分析节末尾,用 `skills/tikz-architecture-diagram` 绘制。
- **求解流程图**(`type=flow`):每问 1 张,放各问开头,用 `visualization.md` 第 5.1.1 节蛇形(横向)TikZ 模板,填 input/process/output。
- **数据图**(`type=data`):从编程手产出的 `results/` 图片里挑(真实反映求解结果),`source` 填详细文件名。

```json
{
  "figures": [
    {"fig_id": "fig1", "type": "arch", "title": "本文总体建模架构",
     "layers": ["数据与题面层", "模型构建层", "算法求解层", "结果输出层", "结论与推广层"],
     "section": "问题分析"},
    {"fig_id": "fig2", "type": "flow", "title": "问题一求解流程",
     "input": "...", "process": "...", "output": "..."},
    {"fig_id": "fig3", "type": "data", "title": "图标题",
     "source": "Q1_各赛季观众数时序折线图.png"}
  ]
}
```

规则:`fig_id` 用 fig1..figN 顺序编号,架构图排 fig1;每问优先选数据图,流程图每问 1 张即可。`source` 填编程手产出的**详细文件名**(如 `Q1_各赛季观众数时序折线图.png`,见 `visualization.md` 第 9 节),不要填 fig1.png 之类。每条图单项都要预先写好 100–150 字的 caption 草稿(第 6.2 节四段式),避免写正文时临时凑一句短标题。论文手未给图单时,兜底直接采用编程手产出的全部可视化 + 每问补一张流程图 + 全文补一张架构图。
