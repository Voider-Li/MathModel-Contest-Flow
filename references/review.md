# 阶段 6:审稿与修改(交付前强制关卡)

审查是交付前的**强制关卡**。审查中发现的问题必须修复——改代码则重跑、改论文则重编译、改交付则重建——然后重新审查,循环直到全部通过。这一步直接决定竞赛评分(合规性、模型正确性、数据严谨、版面观感常是扣分大头)。

本协议融合 mathflow 智能体的"红线/一致性/美观"三级审稿循环与真实竞赛评审的逐条挑刺清单。

## 1. 审稿人角色、分级与九维总览

审稿人以数学建模论文审稿专家身份审查,想象一个挑剔的评委在有限时间里逐页翻看。按**三级严重度**分级列出问题:

| 级别 | 含义 | 处置 |
|---|---|---|
| **红线级** | 篡改题目定义 / 数据泄露 / 结果造假 / 要求未覆盖 / 假数据 / 正文超 30 页 | 必须修复,不通过不交付 |
| **一致性级** | 代码与论文不符 / 数字对不上 / 前后矛盾 / 推导错误 / 方法选取失当 / 数值不合理 / 图表远离引用 / 图片乱码 | 必须修复 |
| **美观级** | 空白、配色、表述、排版微瑕 | 较少时可交付,多则修 |

**九个详细审阅维度**(每一维都必须出结论,不许跳过):

## 2. 方法选取是否合理(一致性级)

方法选错,后面全白做。逐问核问以下六条:

- **方法与问题类型匹配**:回归题用回归/结构模型,优化题给出完整优化模型而不是启发式一把梭,评价题用有依据的指标体系而不是拍系数,预测题交代清楚外推的可信区间。类型判定见 `parsing.md`,选型偏好序见 `modeling.md`。
- **大道至简**:有没有小题大做?一个明显的线性关系上了三层神经网络,是减分而非加分。反过来也查大题小做:明显的多约束调度问题用简单排序糊过去。
- **数据量是否支撑方法复杂度**:样本 20 条却训练深度模型、特征数超过样本数还不做正则、时序仅 8 个点就做 ARIMA——这类"方法与数据不匹配"是典型硬伤。核对样本量、特征数、参数个数三者的比例关系。
- **模型假设是否被满足**:用 OLS 要查残差是否近似同方差与正态、是否存在严重多重共线;用泊松/排队论要查到达过程是否近似无记忆;用马尔可夫要说明状态转移的无后效性。**假设不满足却硬用,必须在论文里显式讨论影响**,不能默默略过。
- **是否有候选方案对比**:`modeling.md` 要求每问给 2~3 个差异化候选并说明选定理由。论文里应能看到"为什么选它、不选另一个"的交代,而不是凭空冒出一个模型。
- **黑箱是否有可解释性补救**:用了随机森林/XGBoost 之类,是否只作稳健性对照?若作主角,是否配了特征重要性/SHAP 等解释?见 `modeling.md`。

判定:六条中任何一条明显不成立 → "失当",列出具体问题与建议替代方法;有疑虑但可辩护 → "存疑",要求论文补一段论证。

## 3. 是否完成题目全部要求(红线级)

建立《题目要求清单》核对表,逐条打勾。列内容:题目原文摘录 → 论文对应章节 → 支撑材料对应文件 → 是否满足。

- 逐问摘出题目的每一个子任务(每个"要求/需分析/需给出/需回答"),论文必须有对应章节且**确实回答了那个问题**,不是泛泛带过。特别注意被藏在长句里的次要要求(如"并讨论其对 X 的影响""同时给出灵敏度分析")。
- 输出层面逐条核对:文件命名、单位(如"预测观众(百万人)" vs "人")、表头列名、保留小数位、必须给出的图表/表格/方案——这些"表面要求"最容易被忽略,却是硬性扣分点。
- 题目提供了哪些数据/附件:是否全部处理并用上;没用到的要给出理由(如"某字段全为缺失,已说明")。
- 检查有没有"题目没要求但论文擅自改变范围/口径"的地方(擅自扩大或缩小都在此列)。
- **每个小问都要有明确的、可指认的答案**。评委找不到答案在哪,等于没答。结论性数字应在该问小结与摘要里各出现一次且一致。

## 4. 公式与定义忠实性:不得自行篡改(红线级)

题目明确给出的公式、符号、口径、约束条件,是**题目定义的契约**。逐条比对三个版本,必须一致:

```
题目原文定义  ↔  论文中的公式/文字  ↔  代码实现
```

- 逐条对照:指标定义(休息间隔、旅行负担、上座强度、出线概率)、约束条件(容量上限、配额、预算)、动态更新公式(状态/参数如何迭代)、归一化口径。
- 只允许**等价改写**(形式变了、数学上完全等价,且注明"等价于题目定义")。不允许悄悄改口径让结果好看——最严重的失分项之一。
- 若数据或客观条件确实不支持题目定义(如题目公式需要某字段而数据缺失),必须**显式写清楚差异与理由**,而不是默默换成自己的定义。

## 5. 谬误与前后矛盾(一致性级)

分两块查:**局部推导谬误**与**全篇前后矛盾**。后者最容易漏,因为分章节写作时每章各自看都对,连起来才露馅。

### 5.1 推导谬误

- 逐式复核:量纲一致;符号先定义后使用、全篇统一;边界条件正确(对数真数 > 0、分母 ≠ 0、clip 范围、归一化范围)。
- 大段推导从假设到结论**完整重推一遍**,不跳步。
- 统计量可重算:弹性/系数/标准误/t/F/R²/残差诊断等,用代码或手算抽查至少一个。
- 公式编号与 `\eqref` 引用一一对应,无孤儿公式、无错引。
- 每问推导充分性:各子问题应含 ≥10 处有实质的公式推导/定义/约束/证明(分散在各小节);检查是否"主要且必要、未与前文重复、未为凑数强加";若某问确实内容较浅写不出 10 个有实质的,不强行扣分(见 `writing.md` §2.6)。
- 常见谬误:相关当因果、以均值代替分布做决策、把 OOB/CV 精度当测试集精度、显著性与效应量混谈、用 R² 判定非嵌套模型优劣、优化模型漏写非负/整数约束导致解不可行。

### 5.2 前后矛盾(逐项交叉核对)

| 核对对 | 查什么 |
|---|---|
| 摘要 ↔ 正文 ↔ 表格 ↔ 附录输出 | 同一关键数字四处是否完全一致(含小数位与单位) |
| 符号表 ↔ 各章公式 | 同一符号是否始终同义;有无一符两义、一义两符 |
| 模型假设 ↔ 后文做法 | 假设了"忽略 X",后文却又建模 X;假设了线性,后文用非线性 |
| 结论文字 ↔ 图表趋势 | 正文说"随 X 增加而上升",图里却是下降或非单调 |
| 问 i ↔ 问 j | 跨问共享的参数/口径/基准值取值是否一致;问 2 的输入是否真是问 1 的输出 |
| 单位与量纲 | 万人/人、公里/米、%/小数、元/万元 是否全篇统一 |
| 模型评价节 ↔ 正文实际 | 评价里说的优点缺点,是否真是本文做法的优缺点(常见照抄通用套话) |

**手段**:`grep` 关键数字在全文出现的所有位置逐一比对。
```bash
grep -n "0\.592\|34\.91\|3862" main.tex        # 关键数字全篇定位
grep -no "R\^2\|R\{2\}" main.tex | head        # 同一统计量的不同写法
```

任何一条矛盾都必须修到"四处一致",不能只改一处。修复后关键数字若有变动,重跑本表。

## 6. 数值是否合理(一致性级)

数字算得出来不等于数字讲得通。逐项体检:

- **量级常识**:人数不是小数、天数不是负数、概率在 [0,1]、比例之和为 100%(容差 ±0.5%)、增长率不出现 3800% 这类离谱值。
- **物理/业务可行性**:调度方案里同一队同一时刻不在两地、容量不超场馆上限、预算不超总额、时间窗不倒序。**把最优解代回原约束逐条验算**,这是最有效的一步。
- **与基线/常识对照**:改善幅度是否可信?模型比基线好 300% 通常意味着基线设错或有泄露;完全零误差意味着标签泄露。
- **有效位数**:统计量给 3~4 位有效数字即可,不写 `0.5923847`;金额与人数按业务习惯取整并注明单位。
- **边界与极端情形**:参数取边界值(0、上限)时模型是否仍有意义;敏感性分析里扰动 ±10% 结论是否翻转(翻转说明结论脆弱,要在论文里如实说)。
- **单调性与符号**:弹性系数、回归系数的正负号是否符合机理预期?与预期相反时必须解释原因,不能视而不见。
- **可复现**:论文引用的每个关键数值都能重跑脚本得到相同结果(见 §8)。

```bash
python solve.py | tee run.log
grep -nE "目标值|R2|改善率|最优" run.log        # 与论文逐一对照
```

## 7. 是否有一定创新(美观级;完全无创新按一致性级处理)

评委在同质化论文里找区分度,创新是拉分项。要求**至少 1~2 处明确可指认的创新点**,且论文里写清"新在哪、为什么有效"。

创新可落在五处(见 `modeling.md`):

1. **模型本身与简化策略**:提出更贴合机理的结构式、给出有依据的简化并论证其误差可控。
2. **求解算法**:针对问题结构设计的加速/剪枝/邻域,而不是套用现成求解器。
3. **结果表示**:用更能说明问题的图表组织方式呈现结论(如把热力图与边缘分布组合)。
4. **结果分析与检验**:设计了额外的验证实验、反事实对照、稳健性检验方案。
5. **推广**:把模型推广到题目未要求但自然相邻的场景,并给出条件。

**伪创新识别(不算创新,别自欺)**:给常规方法起个新名字;把若干现成模块串起来称"融合框架";把参数从 3 个加到 30 个称"精细化";堆砌高级图表;仅换数据集重跑。

判定:找不到任何可指认创新点 → 提升为一致性级,要求补一处真实创新(通常从"结果分析与检验"入手最容易做实)。同时检查创新是否**切实、不离题**——为标新立异而偏离题目要求,反而扣分。

## 8. 代码—论文一致性(一致性级)

- 论文里的每个公式 → 代码里有对应实现,变量名/表达式对得上;论文没写但代码里有、或论文写了代码没有的,都是不一致。
- 论文描述的方法细节(初始化方式、贪心策略、局部搜索邻域、重启次数、停止条件、随机种子)→ 与代码实际行为一致。**代码没有的东西,论文不许写。**
- 论文引用的每个关键数值(目标值、指标、改善率)→ **重跑脚本可复现**,记录运行命令、数据版本、随机种子。
- 附录代码与交付的支撑材料代码是**同一份**(论文用 `\lstinputlisting` 自动加载最终代码,不手抄)。
- 命名/单位/口径在四处统一:论文正文、代码、结果 CSV、README。

```bash
diff <(sed -n '/lstinputlisting/,/^}/p' main.tex) 支撑材料/代码/*.py   # 附录与交付代码一致
python solve.py | tee run.log                                           # 重跑核对关键数字
```

## 9. 数据泄露(红线级)

逐项自查,任何一条命中都要修:

- **时间信息**:时序/按时间展开的数据,训练只用过去;预测某条样本,只用它**发生之前**可得的变量。
- **未来信息特征**:最隐蔽。检查每个特征"开球前是否可知"——"是否淘汰赛/小组赛"提前可知(OK);"该场晋级球队/实际比分/实际观众"开球后才知道(泄露)。凡用"比赛结果"类变量做特征时高度警惕。
- **标准化/归一化**:只对**训练集** fit(算均值/方差/极值),测试与预测用训练集参数 transform。绝不能对全数据一起 fit。
- **全局统计量**:缺失填充值、全局均值、全局极值、embedding 词表等,从全数据(含测试)算出的任何量喂进模型都是泄露。
- **CV/OOB 表述**:测试集无标签时,用训练集 5 折 CV 的 OOB 预测作真实对比,**如实标注**"基于训练集 CV",不冒充测试集精度。
- **外部数据边界**:真实基线/官方数据(如真实赛程)只作评估对比,不参与训练;边界在论文里写清楚。

## 10. 版面审查(图表位置、页数、布局、乱码)

版面是评委的第一印象,也是最容易机检的部分。**先跑脚本拿客观数据,再逐页转图片人眼复核。**

```bash
python scripts/check_layout.py main.pdf --tex main.tex
```

该脚本一次性给出六项结论:图表就近、说明文字字数、单页图表占比、图挨图、正文页数、乱码。退出码非 0 即需修复。

### 10.1 图表放置位置是否合理(一致性级)

- **就近**:每个图表与正文首次引用它的位置**同页或相邻页**,且**内容上紧随引用**(先引用、后出现)。LaTeX 浮动体默认会漂移,必须靠 `[H]` + 源码紧跟引用段 + `\FloatBarrier` 锁死,详见 `writing.md` 第 6.1 节。
- **孤儿图表**:存在图表但正文从未 `\ref` 引用 → 一律视为违规,要么补引用与解读,要么删图。
- **顺序**:图表编号顺序与正文出现顺序一致,不出现"先出现图 5 再出现图 3"。
- **说明文字**:每个 caption **100–150 字**(四段式:这是什么 → 怎么来的 → 关键数字 → 说明什么),不是光秃标题;表题在表上方、图题在图下方,全文统一。见 `writing.md` 第 6.2 节。
- 脚本对应输出:`[3] 图表就近`、`[2] 图表说明文字字数`。

### 10.2 正文页数(红线级)

- **硬性要求:正文(不含附录)不超过 30 页**;且应落在 **21–30 页**区间。
- 超 30 页 → 红线级,必须压缩(手段见 `writing.md` 第 7.5 节:先移代码与长表进附录、删重复解读、砍冗余图表、合并小节、压公式排版)。
- 不足 21 页 → 一致性级,内容偏薄,补结果解读、敏感性分析、假设论证、算法步骤、数据预处理(禁止拉行距/放大图片凑页)。
- **禁止靠改页边距、行距、字号来凑页数**——多数赛事禁止私改模板参数,属违规风险。
- 脚本自动探测"附录"标题所在页来切分;探测不准时用 `--body-end N` 手动指定后复核。

### 10.3 页面布局是否合理:逐页转图片视觉审查(必做)

文本层检查查不出"看起来怎么样"。**把 PDF 逐页转成图片,一页一页看**——这是唯一能发现观感问题的手段,有视觉/多模态能力时必须做:

```bash
mkdir -p review && pdftoppm -png -r 120 -f 1 -l 30 main.pdf review/page
# 产出 review/page-01.png ... review/page-30.png,逐张查看
```

逐页核对清单(每页都过一遍):

- [ ] **图表占比**:这一页图表视觉占位是否 ≤ 2/3?翻开是否给人"整页全是图"的观感?
- [ ] **图挨图**:是否出现两图直接相邻、中间连一句解读都没有?(caption 不算正文)
- [ ] **图文交替节奏**:是否有一整页纯文字、纯公式、或纯图表?
- [ ] **底部空白**:是否有 > 90pt 的大片空白(见 `writing.md` 第 7 节)?
- [ ] **图表完整性**:图是否被页边界截断?表是否跨页且缺表头续行?
- [ ] **图内文字可读**:坐标轴标签、图例、数值标注在正常缩放下是否看得清?是否有文字互相遮盖?
- [ ] **溢出**:公式/表格/TikZ 图是否超出版心右边界?
- [ ] **风格一致**:本页图表配色、字体、线宽是否与全文一致?
- [ ] **标题与内容不分离**:小节标题是否孤零零留在页底而内容跑到下一页?
- [ ] **摘要与标题同页**(第 1 页专项):是否铺满约 80% 版心、按小问成段(背景→针对问题一/二…)、数值与重点方法已加粗?

无视觉能力时的替代手段(能力较弱,不能完全替代):`scripts/check_layout.py` 的占比与图挨图检测 + `writing.md` 第 7.1 节的 pdfplumber 空白测量 + `grep Overfull main.log`。

### 10.4 图片是否有乱码(一致性级)

三道关,缺一不可(详见 `visualization.md` 第 7.1 节):

1. **渲染期警告**:`grep -n "Missing character" main.log` 必须为空;matplotlib 渲染时的 `findfont`/`Glyph missing` 警告一律视为失败。
2. **PDF 文本层机检**:`check_layout.py` 的 `[4] 乱码/缺字` 扫描替换符(U+FFFD)与空心方块(U+25A1/25A0)。
3. **逐页图片目视**:第 10.3 节转出的 PNG 里,逐张确认图内中文没有变成空心方块/问号/错字。**字形缺失但文本层正常的情况只有这一步能发现**,不能省。

发现乱码 → 按 `visualization.md` 第 3.2 节的 `font.family` 列表配方修字体后**重渲图、重编译**,不接受"能看出大概意思"的妥协。

## 11. 全文字体统一(一致性级)

- 正文、标题、图表、表头、页眉页脚:中文宋体、西文数字 Times 风格,全文一个字体语言,不混用黑体/楷体/不同西文字体(图表与正文也必须一致,见 `visualization.md`)。
- 所有 matplotlib 图共用同一组 rcParams(不许逐图手改导致风格漂移)。
- LaTeX 全文统一字体设置;抽查标题、轴标签、图内标注、图题、表头的视觉一致性(在 §10.3 的逐页图片里一并看)。

## 12. 浮夸性检查(美观级)

- 检查论文是否有"浮夸"的地方:自定义很多莫名其妙的术语;图和表表示同一个指标、同一组数据而造成可视化图表冗余等。
- 删故弄玄虚的词,改讲人话(见 `writing.md` 第 5 节降 AI 味)。
- 检查有无 AI 同质化图(雷达图不绘制;热力图仅确实合适时绘制,不滥用,见 `visualization.md` §2.9)、有无为炫技堆砌高级图表。
- **图片文件名是否详细可识别内容**:必须用 `Q{题号}_{内容}_{图表类型}.png` 命名,出现 `fig1.png`/`result.png` 之类无意义命名视为不通过(见 `visualization.md` 第 9 节)。
- **架构图与流程图是否混用**:总体架构图应全文仅 1 张、放问题分析节(用 `skills/tikz-architecture-diagram`);各问流程图用蛇形(横向)TikZ 模板放各问开头。把架构图换标签复制成多张充当流程图,视为浮夸。

## 13. 降 AI 味检查(一致性级)

## 15. 修复循环(直到通过)

1. 汇总全部问题,按严重度排序:**红线级** > **一致性级** > **美观级**。
2. 逐条修复:
   - 改方法选取 → 重建模、重跑、重写该问章节(代价最大,所以 §2 要在阶段 2 就查一遍)
   - 改代码 → 重跑并核对数字
   - 改公式/推导 → 重推并改论文
   - 改版面(图表位置/caption 字数/占比/页数)→ 重编译并重跑 `check_layout.py`
   - 改交付 → 重建 zip
3. 修复后**重跑本协议全部条目 + SKILL.md 质量门禁清单**,含逐页图片复核。
4. 循环直到:红线级与一致性级全部清零;美观级可接受。修复后关键数字有变动时,同步更新摘要/正文/表格/README,保持处处一致(见 §5.2)。
5. **循环上限**:同一问题连续修复 2 轮仍不过时,停下来换思路(不是硬凑),必要时如实告知用户当前状况。

### 15.1 修复片段输出(防截断)
