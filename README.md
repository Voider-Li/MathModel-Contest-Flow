# 数学建模竞赛混合工作流（mathmodel-contest-flow）

> r1 顺序式流水线快速交付 + r0 门控式技能强制质检，兼顾速度与质量。

## 简介

`mathmodel-contest-flow` 是一个面向数学建模竞赛的总控编排 Skill，适用于全国大学生数学建模竞赛（国赛）、美国大学生数学建模竞赛（美赛）及同类建模任务。它将 **r1 顺序式流水线** 的端到端交付速度与 **r0 门控式技能** 的质量约束合成一条可执行流程，确保每个子问题都有可量化的方案对比、独立的数据挖掘章节和独立测试集检验。

## 核心特性

- ⚡ **速度优先**：r1 流水线快速产出报告、图表和论文
- 🛡️ **质量门禁**：12 道强制门禁，任何模式不得跳过
- 📊 **方案对比**：每个子问题必须有基线 vs 主方法 vs 备选的对比表
- 🔍 **独立数据挖掘**：独立成章，覆盖缺失/离群/分布/相关/特征工程
- ✅ **独立检验**：最终指标只能来自从未参与训练的测试集
- 📝 **论文规范**：自动编号、交叉引用、数值可溯源、无编造
- 📚 **文献管理**：先建库再写作，逐条核验，禁止凭记忆补 DOI
- 🔄 **可移植**：不写死任何绝对路径，可复制到任意 Agent 的 skills 目录使用

## 两种模式

| 模式 | 适用场景 | 说明 |
|------|----------|------|
| `lean` | 72 小时赛程（默认） | 保留全部强制门禁，压缩人工决策和审计文件 |
| `submission` | 冲刺国奖 / 赛前演练 | 保留完整证据链（method card、decision ledger、risk probe、QA 审计） |

## 阶段与门禁总览

| 门禁 | 阶段 | 核心产出 |
|------|------|----------|
| G0 | 设置 | `plan.md`、`todo.md`、`session_config.json` |
| G1 | 问题框架 | Qx framing、数据盘点报告 |
| G2 | 方法筛选 | method card、决策留痕、假设与符号表 |
| G3 | 数据挖掘 | `DATA_MINING_REPORT.md`、论文独立章节素材 |
| G4 | 建模实现 | `code/`、`results/`、`RESULTS_REPORT.md` |
| G5 | 对比与稳健性 | `COMPARISON_REPORT.md`、对比表、独立测试集指标 |
| G5.5 | 文献管理 | 文献库、`.bib` / `references.json`、核验记录 |
| G6 | 论文撰写 | 完整论文章节、全部图表被引用 |
| G7 | 最终验收 | `VERIFY_REPORT.md`、提交包 |

## 12 道强制门禁

1. **基线门** — 每个子问题必须有真实可比的基线方法
2. **数据挖掘门** — 独立成章，覆盖变量字典到特征工程全链路
3. **独立检验门** — 按独立单元划分，最终指标仅来自测试集
4. **对比门** — 每问必有基线 vs 主方法 vs 备选对比表
5. **论文门** — 自动编号 + 交叉引用，禁止硬编码图号表号
6. **文献门** — 先建库后写作，逐条核验真伪与引用语义
7. **数值冻结门** — 论文数值只从冻结结果取，写作期禁改
8. **代码可复现门** — 固定种子、版本、路径，提交前全量跑通
9. **图表门** — 每张图必被引用，对比图共坐标系
10. **表达门** — 低性能直说，"最优/显著"必须有统计支撑
11. **流程门** — 多 Agent 不写同文件，赛程设硬性时间点
12. **Agent 约束门** — 禁编数据/文献/结果，不确定必明说

## 快速开始

1. 将本目录复制到你的 Agent skills 根目录下
2. 启动会话，触发 `mathmodel-contest-flow` Skill
3. 按提示设置：排版引擎（Typst/LaTeX）、竞赛类型、语言、子问题数、实现语言（Python/MATLAB）、模式、可用时间
4. 跟随门禁提示逐步推进，每个门禁通过后才进入下一阶段

## 论文章节骨架

1. 问题重述与分析
2. 数据预处理与独立数据挖掘
3. 模型假设与符号说明
4. 各子问题建模与求解（每问末尾放对比总表）
5. 方案/模型对比汇总
6. 模型检验与评价（独立成章，含独立测试集）
7. 结论、优缺点与推广
8. 参考文献与附录
